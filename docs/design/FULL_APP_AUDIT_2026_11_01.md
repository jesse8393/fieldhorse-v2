## Remaining release blockers and risks

1. **Database financial privacy is incomplete.** Live catalog metadata shows `authenticated` can select `fh_contacts.amount`, `fh_contacts.cost` and `fh_clients.total_lifetime_value`; underlying table SELECT policies include every active company member. The patched context RPC redaction does not close direct table access. This requires a deliberate database read contract and coordinated caller migration. Segment filtering also evaluates financial context before matching customers, so restricting the direct columns alone must not leave an inference path. Merely hiding fields in React is insufficient. No real financial rows were read to establish this finding.
2. **Native workflow parity is incomplete.** Native analytics/estimate paths still use old contact stages; some reads filter by record creator rather than company. Native invoice totals/settlement differ from the current web allocation model. Draw inserts are now atomic, but a lost response/retry is not proven duplicate-safe. Mutation hooks now confirm affected rows, but some screen handlers still ignore returned failures or clear drafts before confirmation. Storage deletion is not transactional with index deletion, and upload/index failures still need complete orphan cleanup/reconciliation. The native app must not receive a full production sign-off from successful exports alone.
3. **New conversion and relationship guarantees are local proposals.** Apply the atomic quote RPC before releasing its caller. The independent PostgreSQL concurrency case passed. Exercise the complete production trigger/RLS chain in staging. The six company FKs add alternate PostgREST relationships: deploy explicit-FK query callers first, and establish a compatibility or retirement path for older native/PWA clients before applying those constraints. Do not apply this migration while supported clients still use ambiguous embeds.
4. **DocuSign completion needs a transactional persistence review.** Current code marks the envelope complete before approval persistence, acknowledges some failures, and snapshots live line items rather than an immutable sent snapshot. A signed-document/provider staging test and a retry-safe persistence design are required. No real envelope was sent or signed.
5. **A reproducible full database baseline is not established.** Sixteen original growth/Jobber migration records were recovered with checksums. They have not been reconciled into the active migration order or replayed as a complete schema. Scheduling/configuration side effects, later function replacements and extension dependencies must be reviewed in an isolated restore. Recovery does not close this blocker.
6. **Production migration/deployment validation remains outstanding.** The new migrations are unapplied. Previously prepared invoice-budget and concurrent crew-allocation guards were also absent from the live trigger catalog. Apply reviewed migrations in staging first; exercise valid existing records, legacy associations, role transitions and rollback before an approved production release.
7. **Provider operations are not exactly-once proven.** Resend deduplication has a provider retention window; Twilio/provider success followed by a persistence failure can still require reconciliation. Jobber bulk-sync partial failures and webhook retries need provider-backed testing. Outbound webhook hosts must be explicitly configured and reviewed; no permissive wildcard default is provided.
8. **Dependency debt remains.** Dependency snapshots from the earlier audit pass, not rerun at this checkpoint: root 23 findings (0 critical, 0 high, 21 moderate, 2 low). Native audit: reduced from 48 (1 critical, 15 high) to 35 (0 critical, 5 high, 29 moderate, 1 low). Native remaining high chains include Expo Router/query-string/decode-uri-component and build-time image-size/PostCSS. Do not force an incompatible Expo/React Native major upgrade to make counts green; upgrade with native compatibility and device validation. These counts are dependency graph findings, not a count of demonstrated exploitable application paths.
9. **Platform configuration needs review.** Supabase reports leaked-password protection disabled and an older PostgreSQL patch version. No production configuration was changed during this audit.
10. **Real accounts and physical devices remain release validation.** Exercise create/update/reload for customers/jobs, task complete/Undo, concurrent scheduling, private photos, revoked/demoted roles, exact financial amounts, offline/reconnect, account switching, iOS Safari keyboard/safe areas, Android navigation, native deep links and provider delivery in authorized test accounts. Synthetic records cannot establish these results.

Additional reviewed risks needing follow-up include invited-member re-entry after revocation, campaign/segment relationship validation, public-endpoint rate limits that are per worker instance, and surviving shared-company references when account deletion races with membership changes. These are not silently counted as passed.
