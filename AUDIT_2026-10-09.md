# Fieldhorse full audit and fix pass, 2026-10-09

Audit of the whole product: the web app, the Netlify functions, the live Supabase project, hosting and PWA setup, tooling, docs and a light pass over the Expo app. The fixes are on the branch `claude/audit-fix-pass-2026-10-09` (pull request #216).

## Summary

* **The live site is down, and the code is not the cause.** fieldhorse.io and every Netlify address for the site return Netlify's own "Not Found" page. The fault is at the Netlify team or account level, and only the account owner can fix it.
* **Several serious security holes were open in production and are now closed.** A homeowner holding a proposal link could take over the contractor's job record. Any signed in user could rewrite another company's contract value or write events into its records. Subcontractor tax ids and payment details leaked across contractors. Crew could read every payment and invoice. The database fixes are applied to production and were tested by running real user queries in transactions that were rolled back.
* **The app now works as a team product.** Before this pass, most screens read rows by the person who created them, so an owner never saw a teammate's invoices, clients or schedule, and many edits on a coworker's job silently did nothing.
* **Every check passes on the final branch.** That covers lint, both repo audits, the typecheck, 493 unit tests, the production build and the browser suite.
* **A short list needs the owner.** Restore Netlify, turn on two Supabase Auth protections, apply one cleanup migration, and pull the live schema into the repo. Section 7 has the full list.

## 1. How the audit was done

1. Read only checks against production: Supabase SQL, policies, grants, storage, cron, advisors and migration history, plus HTTP probes of the site.
2. Baseline runs of every repo check on `main` at `40d9735`.
3. Automated finders swept the code in three shards. Each finding in the first two shards went to independent verifiers, who had to trace a real failure path in the code before it counted.
4. Fixers working by area took the confirmed findings and checked each one again before changing anything. The third shard's findings had not been through the verifiers, so the fixers confirmed or rejected them first.
5. Each fix unit was applied to a clean checkout and run through lint, both audits, the typecheck, the unit tests and the build before it was committed, and the later units through the browser suite as well. CI caught one slip after a push (an off scale spacing value), fixed in the next commit.

| Findings | Count |
| --- | --- |
| Confirmed by verifiers, backend shard | 61 (3 critical, 8 high, 21 medium, 29 low) |
| Confirmed by verifiers, frontend shard | 126 (1 critical, 16 high, 54 medium, 55 low) |
| Rejected by verifiers | 1 |
| Not yet verified, handed to fixers to confirm first | 56 |
| Left undecided by verifiers and not acted on | 56 |

Fixers found nearly all of the unverified findings to be real. At least two were not real and were skipped: the build stamp define (it is read at runtime) and a memo dependency warning (the arrays are stable once data loads).

## 2. Production environment

**Website.** Every URL for the site returned Netlify's plain 404 page, including the permanent link of the last good deploy. The team's other site returned the same page, and control sites on Netlify answered normally. DNS and the TLS certificate point at Netlify correctly. The deploy record shows commit `40d9735` as ready. Both sites' records changed within one second of each other on 2026-09-17, which points to an account event such as billing, usage limits or a paused team. The API does not expose the cause.

**Supabase.** Postgres 17 project `pnmhblvslftdzfcdezbw`. When the audit started there were 15 accounts, every company had one member, nobody had signed in for 30 days (the last sign in was 2026-08-04) and there were 63 jobs, leads and quotes. Email confirmation is effectively off, since accounts are confirmed the moment they sign up, and leaked password protection is off.

**Repo versus production.** Production had moved well past this repository. It records 77 applied migrations, has 37 tables that no file here creates, runs five scheduled jobs and seven edge functions. `supabase/README.md` now documents the gap, five of the seven edge functions are captured under `supabase/functions/`, and the TypeScript types are regenerated from production.

## 4. Database changes applied to production

All of these were written without any statement that removes data and verified with rolled back probes run as real users. Apart from 055, none is recorded in `supabase_migrations.schema_migrations`.

| Migration | What it does |
| --- | --- |
| 055 | Installs the shared rate limiter that the public endpoints already called. This one was applied with the migration tool and is recorded. |
| 062 | Child rows take their company from their job. Partners cannot grant themselves jobs. Quote item totals and events cannot cross companies. Partner invite tokens generate again. Anonymous table access is revoked. |
| 063 | Teammates can open coworkers' job files and photos. Buckets get size and type limits. |
| 064 | Crew and foreman lose the money tables. Notifications are visible to their recipient only. Self service writes stay inside the caller's companies. |
| 065 | Sub portal access requires an accepted job invite in that company. Contractor managers and the bound sub can open sub documents. Vendor tax and payment data is hidden from crew. New rows land in the workspace the app is showing, preferring an owner membership. Managers can record quote approvals and revoke customer links on teammates' jobs. Adds eight missing indexes. |
| 067 | Crew and foreman cannot change a job's stage, value, approval or completion, and cannot delete jobs. |
| 068 | Adds `fh_notes.parsed`, which the Notes screen writes. |
| 069 | Lets a user read their own files in the logos bucket, which Storage requires before it will replace or remove a logo. |

Written but not applied: 066 (a nightly purge of expired rate limit rows and old link view events). It removes rows, so it needs a person to run it from the SQL editor. 059a only matters for building a fresh database.

## 5. What changed in the app

**Security and tenancy.**
* The sub portal reaches a vendor profile only in companies where the sub accepted a job invite. It never returns contractor notes and saves only the fields the sub changed.
* Customer link endpoints check job state, claim approvals atomically, hide drafts and never echo database errors.
* Server functions act for the company rather than the row's creator: any owner, admin or manager can send documents, with the owner's branding and a rate limit.
* Account deletion hands shared records to the next owner or admin instead of erasing them.

**Team and workspace.**
* Data hooks query by the active company and key their caches by it.
* People in more than one company can switch workspaces from Settings, the sidebar, the crew screen or the mobile More menu. The choice is remembered and sent to the database.
* Sign in keeps invite links, invitees skip owner onboarding, and sign out flushes offline work, turns off push and clears cached data.

**Money.**
* Payments settle the right invoices in the right order without double counting.
* Draws and schedules split in cents and always sum to the contract.
* Approved change orders count everywhere a balance shows.
* Amounts show exactly on customer documents, negative values read "-$500", and large values never read "1000K".
* Crew see no money and cannot move stages.

**Field work.**
* Schedule edits work across teammates and repeating events keep their time across daylight saving changes.
* Crew labor is no longer counted twice.
* Dictation in Notes no longer repeats words, and the AI parse is saved.
* Imports read real world amounts and skip repeats.
* Offline queues belong to the user who created the work and report anything the server refused.

**Documents.**
* PDFs map characters the built in fonts cannot draw, keep tables and long text off the footer, and print DocuSign anchors on the signature line.
* A completed DocuSign envelope records the approval like the other approval paths.
* About 1,100 lines of unreachable proposal code are gone.

**Hosting and PWA.**
* A missing asset now returns a real 404 instead of a year cached copy of the app page.
* The service worker skips customer links and no longer precaches code the app never runs offline.
* A Content Security Policy ships in report only mode, and customer and invite pages send noindex.
* Icons were regenerated small, and Netlify builds on Node 22.

**Accessibility and design.**
* Sheets, drawers and search keep keyboard focus inside while open and return it on close.
* Tab strips follow the standard keyboard pattern and point at their panels.
* Keyboard focus is always visible.
* Gold, red and green text uses shades that pass WCAG AA contrast in both themes, and several screens that drew dark text on fixed dark panels in the light theme now follow the theme.
* Motion respects the reduced motion setting.

**Forecast and schedule.**
* A failed weather request no longer shows a green "clear to work" state, made up zeros or "Keep crews on plan". The screens say the forecast is unavailable and offer Try again.
* The schedule weather bar shows its status color, which a naming mismatch had hidden.

**Tooling, dependencies and CI.**
* Lint now parses TypeScript, so it covers 446 files instead of 39, runs the React hooks rules, and checks plain JavaScript for undefined names. That last check is the one that would have caught `pdf.js` calling a helper that did not exist.
* The typecheck now also covers the browser test specs and the test configs.
* Unit tests went from 153 in 25 files to 493 in 71 files, and the browser suite gained a forecast failure test.
* CI runs lint, both audits, the typecheck, the unit tests, the build and the browser suite on every pull request, on Node 22.
* Nineteen unused packages are gone, and in range updates took `npm audit` from 17 advisories to 5.
* `.env.example` lists every variable the code reads, with defaults.

## 8. Known gaps that remain

* The public `logos` bucket accepts SVG files (two exist today), and `job-files` has no file type list. The app refuses HTML, SVG and XML uploads and downloads unknown types instead of opening them, but the storage rules themselves allow them.
* Merging duplicate clients runs as several requests, not one transaction. A failure partway through can leave a half merged pair. A database function `fh_merge_clients` would make it atomic.
* Photo thumbnails need either the Supabase Pro plan (image transforms) or a thumbnail written at upload plus a new column.
* Labor rows that were counted twice before this fix are still in the data.
* DocuSign approvals are stored with an approval method the database already allows and are marked as DocuSign in the snapshot, because the live check constraint has no DocuSign value.
* The Content Security Policy is report only. Watch the browser console for a week before enforcing it.
* Payment logging and the offline outbox now have unit tests, but stage transitions, quote approval, job completion, cost recalculation and the quote totals still have no direct ones.
* The Expo app's schema types are older than the web copy, nothing typechecks the app in CI, and its EAS project is not linked yet (see `mobile/README.md`).
* Both the browser and server default to the model id `claude-fable-5`. Confirm it against the current Anthropic model list before launch.
* Supabase's performance advisor still lists unindexed foreign keys and unused indexes, mostly on the growth and Jobber tables that live only in production.
* Lint reports 58 hook dependency warnings in 16 files. Most come from a fallback empty array that is rebuilt while a query loads, which is harmless; each one should still be reviewed on its own, because adding a dependency changes when the code runs.
* The browser test mock seeds three tables that do not exist and none of the time clock, daily log or materials tables, so those screens are not covered by the mocked suite.
* `mobile/eas.json` contains a personal Apple ID email and team id. Moving the Apple ID to an `EXPO_APPLE_ID` secret keeps it out of the repo.
